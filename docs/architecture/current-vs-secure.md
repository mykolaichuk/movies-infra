# Current (naive) vs secure-by-design

What a quick first version usually looks like, what this project does
instead, and the principle behind each change.

| Naive version | This project | Principle |
| --- | --- | --- |
| SQL with a public endpoint and a password in `.env` | Private endpoint, Entra-only auth, managed identity | attack-surface reduction, no secrets |
| Storage account keys in config | Managed identity + data-plane RBAC, shared keys disabled | least privilege |
| SSH (22) open to the Internet | SSH only from the hub agents subnet over peering | segmentation |
| Pipeline with a service principal secret | Agent identity + workload identity federation, no inbound ports on the agent | zero trust, no long-lived secrets |
| Videos at public blob URLs | Served through nginx, storage has no public access | single controlled entry point |
| Cloudflare API token on the VM for certbot | DNS-01 with managed identity, rights only on the app's own zone | least privilege |
| Agent identity is Owner of the subscription | Contributor on one RG + RBAC Administrator limited by an ABAC allow-list | least privilege, blast radius |
| Pipelines change infrastructure on every push | Plan → manual approval → apply on protected environments | separation of duties |
| Terraform state in a local file or a public bucket | Versioned storage, shared keys off, private endpoint only | integrity, confidentiality |
| Downloaded agent/tool binaries trusted blindly | Agent package verified against its SHA-256 | supply-chain security |
| Shared SSH keys copied between laptops | Per-deployment key generated by Terraform, private half only in Key Vault for the agent (next step: Entra ID SSH login, no keys at all) | secret minimisation |
