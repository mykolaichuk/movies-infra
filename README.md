# movies-infra

Infrastructure as code for **Movies**, the demo project of the
*DevOps/DevSecOps Practices* research club at Zhytomyr Polytechnic State
University.

The project is split into three repositories, one per layer of responsibility:

| Repository | Tool | Answers the question |
| --- | --- | --- |
| **movies-infra** (this one) | Terraform | *What exists in Azure?* |
| [movies-configuration](https://github.com/mykolaichuk/movies-configuration) | Ansible | *How is each VM configured?* |
| [movies-app](https://github.com/mykolaichuk/movies-app) | Node.js | *What does the application do?* |

Want your own copy running? Go to
[Reproducing the project](#reproducing-the-project).

## Layout

```text
bootstrap/           one-off layer, applied by a human from a local host
stack/               everything else, applied by the pipeline on the self-hosted agent
pipelines/           Azure Pipelines YAML
docs/architecture/   C4 model as code + data flows, SPOFs, secure-by-design notes
backend.hcl          shared remote-state settings (generated by bootstrap, then committed)
```

## Architecture

Start with [`docs/architecture/workspace.dsl`](docs/architecture/workspace.dsl):
one Structurizr model renders the C4 **Context**, **Container** and
**Deployment** views. Supporting notes:

- [data flows](docs/architecture/data-flows.md)
- [single points of failure](docs/architecture/spof.md)
- [current vs secure-by-design](docs/architecture/current-vs-secure.md)

Key decisions in one breath: Sweden Central; hub-spoke VNets with peering;
self-hosted agent with no inbound ports; Azure SQL, Storage and Key Vault only
through private endpoints; managed identities instead of secrets; workload
identity federation for the service connection; approvals before every change.

## Order of operations

1. **bootstrap** – once, from the operator's machine: see [`bootstrap/README.md`](bootstrap/README.md).
2. **stack** – `pipelines/infra.yml`: plan → approval → apply.
3. movies-configuration pipeline configures the app VM.
4. movies-app pipeline builds, tests and deploys the application.

## Reproducing the project

The three repositories on GitHub are a template: nothing in them is connected
to a running environment, and no pipeline runs on GitHub. To deploy your own
copy, import them into your own Azure DevOps project and follow the steps
below. Everything is created in your subscription and costs money while it
exists; remove it with [Teardown](bootstrap/README.md#teardown) when done.

### What you need

- An Azure subscription where you are **Owner**, plus an Entra ID role that
  can grant Microsoft Graph application permissions (Privileged Role
  Administrator or Global Administrator).
- vCPU quota for the Arm64 `Bpsv2` family in the region (default
  `swedencentral`): two `Standard_B2pls_v2` VMs, the build agent and the app.
- An Azure DevOps organisation where you are Project Collection
  Administrator, with a self-hosted parallel job (the free tier has one).
- A DNS zone you control (for example `example.com` at Cloudflare) to
  delegate the app's host name (for example `movies.example.com`) to Azure
  DNS.
- A [TMDB](https://www.themoviedb.org/settings/api) **API Read Access Token**.
- On your machine: Azure CLI, Terraform >= 1.9, Git and `ssh-keygen`.

### Steps

1. **Import the repositories.** Create a project in Azure DevOps, then for
   each repository *Repos → repository list → Import repository*, with the
   clone URL below. Keep the repository names.

   ```text
   https://github.com/mykolaichuk/movies-infra.git
   https://github.com/mykolaichuk/movies-configuration.git
   https://github.com/mykolaichuk/movies-app.git
   ```

2. **Put in your values.** In your movies-infra, edit
   [`stack/settings.tfvars`](stack/settings.tfvars) (`domain_name`,
   `admin_object_id`, optionally `app_admin_object_ids`) and commit it to
   `main`. These are the only committed values that are specific to you.
3. **Bootstrap**, once, from your machine:
   [`bootstrap/README.md`](bootstrap/README.md). It creates the state
   storage, the hub network, the build agent, the agent pool `movies-pool`,
   the service connection `sc-movies-azure` and the environments with
   approvals, and it ends with committing the generated `backend.hcl`.
4. **Create the pipelines.** *Pipelines → New pipeline → Azure Repos Git →
   repository → Existing Azure Pipelines YAML file*, then *Save* (not *Run*)
   under exactly these names; `infra` and `configure` are referenced by the
   pipelines that follow them (`resources.pipelines`):

   | Name | Repository | YAML file |
   | --- | --- | --- |
   | `infra` | movies-infra | `/pipelines/infra.yml` |
   | `infra-validate` | movies-infra | `/pipelines/validate.yml` |
   | `set-secret` | movies-infra | `/pipelines/set-secret.yml` |
   | `configure` | movies-configuration | `/pipelines/configure.yml` |
   | `configure-validate` | movies-configuration | `/pipelines/validate.yml` |
   | `app` | movies-app | `/pipelines/app.yml` |

5. **Infrastructure.** Run `infra` and follow
   [`stack/README.md` → First run](stack/README.md#first-run): permit the
   service connection, read the plan, approve, then delegate `domain_name`
   to the Azure name servers from the Outputs stage.
6. **TMDB token.** Run `set-secret` as described in
   [Setting a third-party secret](pipelines/README.md#setting-a-third-party-secret).
   Do it before the app is deployed: the app reads the token at start-up.
7. **Configuration.** A successful `infra` run starts `configure`. Permit
   the resources it asks for, read the Preview, approve. See
   [its pipeline notes](https://github.com/mykolaichuk/movies-configuration/blob/main/pipelines/README.md).
8. **Application.** A successful `configure` run starts `app`. Permit the
   resources it asks for; when it is green, open
   `https://<domain_name>/admin`, sign in with the account from
   `admin_object_id` and press **Import starter catalog**.
9. **Optional: PR checks.** Add the branch policies listed in each
   repository's `pipelines/README.md` (Azure Repos ignores YAML `pr:`
   triggers).
